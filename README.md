# quote-card（名言卡片）

Yunzai 名言卡片生成插件：引用一条消息回复 `#名言`，生成精美(其实并不精美)的玻璃质感卡片。

## 安装

进入 Yunzai 的 `plugins` 目录，克隆本仓库：

```bash
cd plugins/
git clone https://github.com/Looking08/yunzai-plugin-quote-card.git
```

> 依赖 Yunzai 自带的 puppeteer 渲染（`lib/puppeteer/puppeteer.js`），无需额外安装。

仓库带有 `package.json`（`name: yunzai-plugin-quote-card`），方便插件管理器 / 插件市场识别名称与版本。
插件入口 `index.js` 用到 Yunzai 运行时的相对路径（`../../lib/plugins/plugin.js`），所以**安装位置仍然必须是
`plugins/<插件目录>/`**，不能只作为一个普通 npm 依赖平铺在 `node_modules` 里。

## 用法

| 命令 | 说明 | 权限 |
|------|------|------|
| `#名言` | 引用一条消息后发送，生成名言卡片 | 所有人 |
| `#名言2` | 同上，使用另一套卡片样式 | 所有人 |
| `#添加名言照片` | 一次可发多张图 + 指令，自动按顺序排号 | 主人 |
| `#添加名言照片N` | 从槽位 N 开始依次排（N 上限 100） | 主人 |
| `#删除名言照片N` | 删除指定槽位的背景 | 主人 |
| `#名言照片列表` | 查看已上传的背景图，以合并转发形式发送 | 默认所有人，可在锅巴关闭 |
| `#名言帮助` | 以图片介绍插件功能与指令 | 所有人 |

### 批量添加背景

直接一次发 **多张图片** + `#添加名言照片`（不带数字），按发送顺序自动接在末尾：

```
[图1][图2][图3] #添加名言照片
→ ✅ 已保存 3 张：#1 ~ #3
再发 [图4][图5] #添加名言照片
→ ✅ 已保存 2 张：#4 ~ #5
```

想指定起点就写数字，多张图会从该槽位往后连续占用：

```
[图6][图7] #添加名言照片10
→ ✅ 已保存 2 张：#10 ~ #11
```

超过 100 的部分会被丢弃并在回复里提示；单张失败不影响其它张。
引用一条带图的消息 + 指令也可以，同样支持多图。

### `#名言照片列表`

**直接发一张图**（不再包合并转发）。整张图就是一页完整的清单：顶部是总数，
每张缩略图左上角带槽位编号，底部是添加/删除提示与可见性说明。

槽位编号固定显示在缩略图上层，不会被图片盖住。

- 默认**所有人**都能查看；锅巴里关掉「照片列表允许所有人查看」后，只有主人可用（非主人触发时静默无响应）。
- 非主人查看时，图上不会出现「#删除名言照片N」的删除提示。
- 列表一次最多显示 `listLimit` 张（默认 24，可在锅巴配置里调 4~60），超出的会在顶部标注「本页展示 X 张」。

### `#名言帮助`

渲染一张图片版说明书，背景使用 `resources/help-bg.jpg`，上面覆盖深色蒙版保证文字可读。

## 自定义背景（可选）

背景图为可选功能，未设置时使用随机纯色玻璃卡片。如需自定义：

1. 一次发一张或多张图 + `#添加名言照片`，自动从 #1 往后排（也可以写 `#添加名言照片10` 指定起点）
2. 生成卡片时会从已设置的背景里随机挑一张
3. `#名言照片列表` 可以确认到底传了哪些

背景图保存在 `resources/backgrounds/` 目录下，该目录运行时会自动创建。

## 配置

配置文件为 `config/config.json`（相对插件目录），首次写入时自动创建，已加入 `.gitignore`。

```json
{
  "quality": 92,
  "randomBackground": true,
  "listLimit": 24,
  "listPublic": true
}
```

| 字段 | 说明 | 范围 |
|------|------|------|
| `quality` | 卡片 JPEG 质量 | 60 ~ 100 |
| `randomBackground` | 生成卡片时是否从已上传背景中随机取图 | `true` / `false` |
| `listLimit` | `#名言照片列表` 单次展示上限 | 4 ~ 60 |
| `listPublic` | `#名言照片列表` 是否允许所有人查看（**默认开启**） | `true` / `false` |

配置读取失败时自动回落到默认值，不会影响插件启动。

## 锅巴（Guoba）适配

仓库自带 `guoba.support.js`，安装锅巴插件后会出现在锅巴的插件配置面板里，
可视化调整上面四个配置项。`pluginInfo.name` 为 `yunzai-plugin-quote-card`。

> 锅巴只提供「配置项表单」，没有文件上传 / 图片浏览组件，所以背景图的上传、
> 查看、删除仍然只能通过聊天指令完成 —— 这也是 `#名言照片列表` 存在的原因。

## 说明

- 引用消息的文字/图片提取按四级回退：
  `e.source` → `e.getReply()` → **redis 消息缓存**（按 `ref_msg_idx` 反查，
  `wind-msg:group:<群>` / `wind-msg:private:<用户>` 的 ZSET）
  → **原始事件摘要**（`raw_event.d.msg_elements[message_type=103].content`
  或 `parallel_message.msg_nodes[].content`）。
  后两级是为 QQ 官方机器人（QQBot 适配器）准备的 —— 它不设 `e.reply_id` / `e.source`。
- 卡片文字过长会自动缩小字号。
- 插件为 ESM（`"type": "module"`），要求 Node.js >= 18。

### QQ 官方机器人限制

1. **被引用消息的作者经常拿不到**。协议在引用时通常只下发内容，`msg_elements[].author` 为空。
   作者按 `msg_elements[].author`（有则最准）→ 发起引用的人 → 发消息的人 逐级回落：
   **私聊一定正确**（都是同一人），群里引用别人的话可能张冠李戴。
   若被引用消息还在本地缓存里（第 3 级命中），作者是准确的。
2. 头像走 `q.qlogo.cn/qqapp/<机器人appid>/<openid>/0`，appid 从 `bot.info.appid` 取，
   **不是 `self_id`**（两者不同，用错会 404 后静默空白）。
3. 机器人默认只能收到 @它 的消息（未开「全量消息」时），
   这类群里的普通消息不会被 bot 收到，但仍能通过第 4 级兜底正常引用成卡。
4. 消息缓存默认保留 3 天（`Bot.saveTimes`）。

另外 QQBot 的 `user_id` 是 `appid:openid` 复合 id，不是 QQ 号；
名片取 `sender.card`，头像用 `sender.avatar`，显示效果与 QQ 号一致。
